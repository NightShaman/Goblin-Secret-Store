# Goblin Secret Store

Burrow mod providing an operator-managed encrypted credential vault and explicit per-record agent access. No OAuth, sync, or automatic rotation. See [API-CONTRACT.md](API-CONTRACT.md) for UI integration.

## Storage and installation lifecycle

Requires Node **22.13+** (`node:sqlite`; tested on 22.23.2 and 24.20.0). No npm runtime dependencies.

The vault lives at **`$BURROW_RUNTIME_ROOT/mods/mod-data/goblin-secret-store`** when the runtime root is configured (stock container: `/data/mods/mod-data/goblin-secret-store`, on its existing persistent `/data` volume). Otherwise it falls back to `$HOME/.local/share/goblin-secret-store`, not the mod source tree. Set absolute `GSS_DATA_DIR` in the Burrow service environment to relocate it. The directory is mode 0700; `vault.sqlite` and the independent random 32-byte `master.key` are mode 0600. SQLite DELETE journal mode avoids a persistent WAL; protected values are encrypted before reaching SQLite. No core settings/secrets API or core key is used by the vault. Core owns the live tool/provider catalog; authorization for these mod-authorized tools is the record ACL (see below).

Supported Core discovery reserves/skips `mods/mod-data`; it is not a mod installation or a failed mod catalog entry.

Core `src/mod-distribution.mjs` `swapMod` renames/replaces the complete source directory and deletes its backup after successful activation. Uninstall removes that source directory. Neither touches this separate vault directory: upgrade/re-enable/restart retain records; uninstall intentionally retains the vault. To erase permanently, stop the mod and explicitly delete the vault directory. Do not put `GSS_DATA_DIR` under any source installation directory. Containers **must mount the vault directory on a persistent volume** (or mount the containing home); source-upgrade independence does not imply container filesystem durability. Do not run multiple Burrow instances against the same vault. The OS service account and machine administrator can read the key and DB; this is not protection against host compromise.

Missing key with an existing database fails closed. Preserve both files for filesystem recovery. Prefer portable backups: passphrase-encrypted export includes source key and encrypted records, validates and decrypts everything before one SQLite replacement transaction, then re-encrypts under the destination key. Restore does not replace local management credentials. All restored ACLs are inactive—even matching IDs—and require the ACL reassignment operation. Export excludes local password hashes, sessions, audit, and live references.

## Authentication and access

Core routes provide trusted `{enabled,authenticated}` from verified operator auth. Only `authenticated:true` is accepted in core mode; API bearer tokens are not operators. When core authentication is disabled, the first browser visitor may set a >=12-character mod password. **This approved bootstrap assumes a trusted network: isolate the service until the intended operator claims it.** No CLI setup is necessary. Passwords use random salt and scrypt (N=32768,r=8,p=1, 32 bytes); bootstrap uses an immediate SQLite transaction and sessions use 256-bit random tokens. Sessions are memory-only, expire after one hour, and are invalidated on observed auth-mode transitions or host restart. An auth on/off round-trip with no intervening mod request cannot be observed by this core contract; restart the mod when changing auth configuration to guarantee invalidation in that case.

Use HTTPS. Local session tokens belong in memory, never localStorage or logs. All management routes including audit/export/restore are gated. No endpoint reveals protected field plaintext to the browser, including after creation. To change a protected value, replace it; omit the value to preserve it on edit. Public fields and names are intentionally unencrypted metadata: never put secrets there. Agent responses exclude ACL lists.

Each protected field uses AES-256-GCM, random 96-bit nonce, and AAD binding record ID/version/field name/type/protection. Agent identity comes only from core caller context. Default record ACL is deny; explicit one/several/all record grants control both reference issuance and consumption. **All agents plus Save is the explicit choice, with no second confirmation dialog; it includes future agents.** Agent tools issue opaque references, not decrypted values. Consumption rechecks exact agent/session/conversation, version, expiry, and live ACL. The tools register as `mod-authorized`: current Core makes a live enabled provider available without stored per-agent MCP grants. Removing a Core per-agent grant is therefore not a revocation mechanism. Revoke the record ACL or disable the provider. Core rechecks provider availability at consumption. Mutations replace an opaque persisted version identity and revoke prior references; restore assigns fresh identities even for deleted/reintroduced IDs, and restart discards references. Legacy numeric versions remain readable and are replaced on mutation. A grant does not restrict a consumer to a destination, host, command or task; revocation cannot retract plaintext already delivered. Trust the host and authorized consumers. Auditing records redacted issuance/use/denial identifiers and management mutations, never field names/values or passwords; public credential names are snapshotted for authorized events.

## Limits and tests

Defaults: 1000 records, 64 fields/record, 64 KiB/field, 16 MiB JSON request body (exports must fit the full restore envelope), 10000 retained audit events, 10000 live references (60s), 256 live sessions (1h), 10 password attempts/minute globally, audit reads cursor-paginated, newest first, 1–500 events/page without a 1000-event read cap. `GSS_LIMITS_JSON` can override positive integer `records`, `fields`, `valueBytes`, `bodyBytes`, `audit`, `refs`, `sessionMs`, `refMs`. Defaults constrain child memory, synchronous SQLite/scrypt work, IPC payloads and audit growth. Exports budget `JSON.stringify({passphrase,backup})` in UTF-8, including escaping and passphrase overhead, against `bodyBytes`; near-limit exports fail with `backup_limit` rather than emit an unrestorable archive. Restore using the unchanged archive and passphrase, without extra request properties. The tested Core HTTP default is 96 MiB, above this mod’s default 16 MiB, and its generic mod IPC adds no smaller body cap. Operator/proxy limits may be smaller and remain authoritative: configure their request cap at least as high as `bodyBytes`, and do not raise the mod limit beyond the host budget. Retain a verified recovery drill. Password attempt limits are deliberately global to avoid trusting spoofable client-IP headers; hostile visitors can temporarily deny login. Backup/restore scrypt is authenticated and synchronous, so large exports temporarily block this mod host. No background expiry worker or password recovery/change API in v1. Lost local password recovery requires an authenticated core operator or offline administrator recovery; backups never export it.

## UI placement

Credential management, ACLs and encrypted backup/restore live only in Settings.
Authenticated audit lives only in Archive → MODS → Goblin Secret Store, with
UTC date filtering and cursor pagination over the mod-owned retained history.
There is no control-panel destination. Local passwords/sessions remain in memory;
Settings and Archive share a memory-only session scoped to runtime/mod identity; date remounts retain that session until logout, expiry, auth-mode change or reload. Authentication loss invalidates in-flight management loads and clears cached management metadata across mounted surfaces; cached record interactions also recheck the current session before rendering metadata.
